# 05. 레퍼런스 분석

## 분석 기준

- 기준 문서: docs/01-site-purpose.md, docs/04-site-wireframe.md
- 사이트맵(03)은 변경하지 않는다. 와이어프레임(04)은 이 분석에서 나온 제안 중 B, C, D 세 가지만 변경하기로 확정했고, 제안 A(홈 하단 FAQ)는 채택하지 않았다. 그 밖의 적용은 기존 구조 안에서 색, 여백, 정보 위계, 버튼·카드의 시각 표현으로 한정한다.
- 분석을 작성할 때는 두 기준 문서의 원본을 읽지 못해 기획 단계에서 확정한 내용을 기준으로 삼았다. 이후 원본(01~04)을 읽고 대조해, 달랐던 변경 C의 내용을 이 문서에서 고쳤다. 나머지 아래 내용은 원본과 일치한다.
- 기준으로 쓴 내용
  - 주요 방문자: 매달 간식을 사는 집사(다묘 가정 포함), PC 중심
  - 핵심 행동: 박스 구성 후 정기배송 신청 (배송 주기는 매달 1회 고정)
  - 원하는 인상: 쉽고 재미있게 고르는 사이트, 간편하고 합리적인 정기배송
  - 피할 방향: 쇼핑몰식 빽빽함, 복잡한 구매 과정
  - 페이지 구성: 홈(P01) → 박스 만들기(P02) → 정기배송 신청(P03)
  - 홈 구성: 이미지가 전체를 채우고 중앙에 글씨가 있는 첫 화면 → 베스트 간식 박스 → 다른 집사들이 만든 간식 세트 → 정기배송 안내(흐름도, S03)
  - P02: 왼쪽 간식 선택 + 오른쪽 고정 '내 박스'
  - P03: 구성 확인(고양이 이미지 왼쪽 + 구성품 오른쪽), 신청 완료 안내(S09)는 팝업
- 확인 방법: 링크의 페이지 텍스트와 사용자가 첨부한 화면 캡처(Scrumbles, Bark). 확인하지 못한 폰트명, 색상값, 간격은 적지 않았다.

## 1. 오아시스마켓

- 링크: https://www.oasis.co.kr/main
- 접근 상태: 접근 가능. 페이지 텍스트로만 확인했고 화면 캡처는 없다. 그래서 색이 적용된 위치, 버튼 색, 글자 크기, 여백은 확인하지 못했다. 페이지 끝부분 약 2천 자(하단 영역)는 읽지 않았다.

### 확인한 특징

- 제목과 본문 크기 관계: 확인 불가. 구조만 확인했다. 섹션마다 제목과 '상품 더보기' 링크가 붙고, 그 아래에 상품 이름과 가격이 나열된다.
- 여백: 확인 불가. 다만 한 페이지에 메인 배너 18장, 빠른 카테고리 아이콘 10개, 특가 탭(타임특가·한정특가·뷰티∙리빙·상생특가), 상품 섹션 7개가 이어져 정보량이 매우 많다.
- 컬러: 페이지의 theme-color 메타값이 초록(#6ca437)으로 지정되어 있다. 이 값이 버튼이나 배경에 그대로 쓰이는지는 확인하지 못했다.
- 상품 카드 정보: 할인율, 판매가, 원가(취소선), 장바구니 담기·위시리스트 버튼, 한정 수량 표시, 품절 표시, 타임특가 시간 표시가 함께 들어간다.
- 구매 흐름: 장바구니에 담으면 팝업에서 '장바구니로 이동 / 계속쇼핑'이 나오고, 일반 장바구니와 별도로 '정기배송 장바구니' 링크가 있다.
- 메시지: 페이지 설명 문구가 가격과 품질을 앞세운다.
- 이 특징이 만드는 인상: 초록 지정색과 높은 정보 밀도가 합쳐져, 신선식품 대형 마트처럼 믿음직하고 가격이 강점인 인상을 준다.

### 적용할 페이지·섹션과 이유

1. 사이트 전체의 기본 색 방향(초록)
   - 오아시스가 초록을 지정색으로 쓰는 방식을 기본 방향으로 삼는다.
   - 이유: 수제간식 정기배송에는 신선함과 안심이라는 신뢰 이미지가 필요하고, 초록이 그 방향과 맞다. 정확한 색상값은 이 문서에서 정하지 않는다.
2. 홈 '베스트 간식 박스' 섹션 [와이어프레임 변경 D]
   - 섹션 제목 옆에 '더보기' 링크를 두고 박스 만들기(P02)로 연결한다.
   - 이유: 핵심 행동(박스 구성)의 입구가 홈 중간에도 생겨서, 첫 화면까지 올라가지 않아도 바로 시작할 수 있다.

### 적용하지 않을 부분

- 한 페이지에 상품 섹션 7개 이상, 배너 다수, 특가 탭, 시간 카운트다운, 한정 수량·품절 표시: '쇼핑몰식 빽빽함' 회피 방향과 충돌한다.
- 할인율과 원가 취소선 중심의 가격 표시: 가격·배송비 안내를 홈에 꼭 넣지 않기로 한 방향과 맞지 않고, 가격은 박스 만들기에서 바로 바뀌는 체험으로 보여준다.
- 일반/정기 장바구니 분리, 배송지·배송 가능 지역 팝업, 로그인·마이페이지 중심의 상단 메뉴: 골라담냥은 정기배송 한 가지(월 1회 고정)와 3페이지 구성이라 필요하지 않다.
- 수십 개 분류의 전체 카테고리 메뉴: 간식 둘러보기를 박스 만들기에 통합한 구조와 맞지 않는다.
- 상품 이름 앞의 특징 라벨: 기존 와이어프레임에 없는 요소를 더하게 되므로 적용하지 않는다.

## 2. Scrumbles

- 링크: https://www.scrumbles.co.uk/
- 접근 상태: 접근 가능. 페이지 텍스트와 사용자가 첨부한 화면 캡처(상단~첫 섹션)로 확인했다. 캡처에 없는 아래쪽 섹션의 색은 확인하지 못했다.

### 확인한 특징

- 제목과 본문 크기 관계: 캡처 기준으로 히어로 제목이 본문보다 훨씬 크고, 제목 위의 작은 라벨과 아래의 본문까지 세 단계로 구분된다. 제목은 가로로 눌린 굵은 대문자풍 서체, 본문은 둥근 손글씨풍 서체로 보인다. 서체 이름은 확인하지 못했다.
- 여백: 캡처 기준으로 라벨, 제목, 본문, 버튼, 카드가 서로 간격을 두고 쌓인다. 섹션 구분은 빈 공간보다 배경색 띠의 전환으로 한다. 위에서부터 밝은 주황 띠, 청록 헤더, 흰 카테고리 줄, 연한 민트 히어로, 흰 띠, 연한 하늘색 카드 순서다.
- 컬러
  - 상단 안내 띠: 밝은 주황
  - 헤더: 중간 톤의 청록(민트 그린) 바탕, 흰 로고, 짙은 청록 글씨
  - 히어로: 헤더보다 연한 민트 바탕, 글씨는 짙은 청록 한 가지로 통일
  - 구독 버튼(헤더 안): 짙은 청록 알약형, 흰 글씨
  - 주요 버튼 두 개: 짙은 베리 레드 알약형, 흰 글씨. 민트 바탕과 대비되는 색이다.
  - 보조 진입 카드: 흰 둥근 카드와 짙은 청록 원형 화살표 버튼
  - 카테고리 아이콘: 분홍, 산호, 연보라, 연파랑의 파스텔 원형 배경
  - 하단 카드: 연한 하늘색 배경, 사진도 같은 계열의 푸른 배경
- 주색: 민트~청록 계열의 초록이다. 글씨와 보조 버튼까지 청록 한 계열로 묶고, 가장 중요한 버튼만 베리 레드로 분리했다.
- 이 특징이 만드는 인상: 한 계열의 색을 면, 글씨, 보조 버튼에 반복해서 안정감을 주고, 파스텔 원형과 베리 레드가 발랄함을 더한다.

### 적용할 페이지·섹션과 이유

1. 홈 첫 화면의 헤더
   - 헤더를 초록 계열 바탕에 두고 글씨는 같은 계열의 짙은 색 한 가지로 통일한다.
   - 이유: '초록이 기본'이라는 인상이 첫 화면에서 바로 정해진다.
2. 홈 섹션 사이의 구획 [와이어프레임 변경 B]
   - 섹션 사이를 연한 초록 계열 면과 흰/크림 면의 전환으로 나눈다.
   - 이유: 정보를 줄이지 않고도 구획이 되어 '빽빽함'을 피하면서 지루하지도 않다.
3. 핵심 버튼 한 종류만 면 색과 대비시키기 [결정 필요]
   - 가장 중요한 행동(박스 만들기 시작, 정기배송 신청) 버튼만 주변 면 색과 대비되는 색으로 분리한다.
   - 이유: 핵심 행동이 '박스 구성 후 정기배송 신청'이라 한눈에 보여야 한다. 초록 면 위에서는 초록 버튼의 대비가 약해질 수 있어서, 대비색(보라 계열 후보)을 쓸지는 따로 정해야 한다.
4. 홈 '베스트 간식 박스'와 '다른 집사들이 만든 간식 세트' 카드의 이미지 배경
   - 파스텔 원형이나 연한 단색 면 위에 고양이·간식 이미지를 올린다.
   - 이유: 사진 배경이 제각각이어도 색 면으로 통일되고 발랄함이 생긴다.
5. 정기배송 안내 흐름도(S03)
   - 단계 표시를 파스텔 여러 색으로 구분하고, 글씨는 짙은 색 한 가지로 통일한다.
   - 이유: 글자 대신 흐름도로 간단히 보이려는 방향과 맞고, 단계가 색으로 구분된다.

### 적용하지 않을 부분

- 베리 레드를 그대로 쓰는 것: 골라담냥의 색 방향은 초록+보라라서, 대비색은 보라 계열 후보로 따로 검토한다.
- 퀴즈로 맞춤 레시피를 찾는 진입 카드: '직접 골라 담는' 컨셉과 다르고, 기존 와이어프레임에도 없다.
- 상단의 할인·무료배송·구독 할인 안내 띠: 가격·배송비 강조를 최소화하는 방향과 맞지 않다.
- 말장난 문구, 로고, 사진: 복제하지 않고 구성과 색 사용 원리만 참고한다.
- 캡처에 없는 하단 섹션의 색: 확인하지 못했으므로 적용 근거로 쓰지 않는다.

## 3. Bark

- 링크: https://bark.co/
- 접근 상태: 접근 가능. 페이지 텍스트와 사용자가 첨부한 화면 캡처(구독 박스 소개 섹션)로 확인했다. 캡처 외 섹션의 시각 값은 확인하지 못했다.

### 확인한 특징

- 제목과 본문 크기 관계: 캡처 기준으로 섹션 제목이 매우 크고 굵게 가운데에 놓이고, 그 아래 상품 이름은 중간 크기, 항목 3줄은 작은 본문이다. 세 단계의 차이가 뚜렷하다.
- 여백: 캡처 기준으로 흰 바탕에 제목 위아래와 좌우 컬럼 사이 여백이 넓다. 이미지 쪽은 연한 파란 둥근 패널 위에 큰 사진을 올리고, 사진 일부가 패널 밖으로 튀어나오게 배치했다. 오른쪽은 선택 → 이름 → 3줄 요약 → 큰 버튼 → 한 줄 혜택 순서로 간격을 두고 쌓는다.
- 레이아웃 구성
  - 페이지 전체 순서(텍스트 기준): 상단 프로모션 → 구독 박스 소개(4종 선택) → 카테고리 4칸 → 후기 → 베스트셀러 → 팀 소개 → FAQ → 판매처 로고 → 푸터
  - 구독 박스 소개는 왼쪽 이미지, 오른쪽 선택·요약·버튼의 2컬럼이다.
- 선택 방식: 박스 종류 4개가 알약형 토글로 나열되고, 선택된 것만 진하게 채워지고 나머지는 외곽선이다. 종류마다 3줄 요약(구성, 매달 새 테마, 가격과 무료배송)과 버튼 하나가 붙는다.
- 컬러: 흰 바탕, 짙은 남색 글씨와 선택 토글, 밝은 하늘색 알약형 버튼, 연한 파란 패널, 알록달록한 상품 사진이다. 페이지의 theme-color 메타값은 아주 연한 푸른 흰색(#f2f7fc)이다. 이 값을 UI 색으로 확정하지는 않는다.
- 상품 카드: 이미지, 이름, 가격, '+ Add' 버튼으로 구성된다.
- 이 특징이 만드는 인상: 여백이 넓고 제목 크기 대비가 분명해서 정돈된 느낌이고, 즐거움은 색보다 사진과 상품 캐릭터에서 나온다.

### 적용할 페이지·섹션과 이유

1. P03 정기배송 신청의 '구성 확인' [와이어프레임 변경 C]
   - 왼쪽 고양이 이미지는 연한 색 패널 위에 올리고 일부를 패널 밖으로 나오게 한다. 오른쪽(S07)은 '구성품 → 요약·가격 자리(가격은 추후결정)' 순서로 쌓고, 큰 버튼은 이 흐름의 끝에 오는 B06 하나로 한다. B06은 와이어프레임에서 S08(신청 입력)에 있어 옮기지 않고 위치만 명시한다.
   - 이유: 이미 정한 좌우 구성과 같고, 신청 직전 화면에서 선택지를 줄여 '복잡한 구매 과정'을 피한다.
2. P02 오른쪽 고정 '내 박스' [와이어프레임 변경 C]
   - 영역 안을 '구성(S05) → 요약·가격(S06) → 신청 버튼 하나(B04)' 순서로 두고, 버튼은 영역 폭 가득 크게 한다. 기존에 S05와 S06에 따로 있던 같은 목적지의 버튼(B04, B05)은 B04 하나로 합친다.
   - 이유: 담는 동안 가격과 개수가 바뀌고 최종 행동은 신청 하나라서, 시선이 아래로 내려가며 끝나는 단일 흐름이 된다.
3. P02 간식 카드의 정보 위계 (시각 처리만)
   - 이미지, 이름, 가격, 담기 버튼을 가장 단순하게 보이도록 크기 차이를 분명히 둔다. 새 요소는 더하지 않는다.
   - 이유: 카드 정보가 가볍게 읽혀서 맛과 개수를 쉽게 고르는 인상을 만든다.
4. P02·P03의 선택 컨트롤 스타일 (시각 처리만)
   - 와이어프레임에 이미 있는 선택 컨트롤에 한해, 선택된 값만 진하게 채우고 나머지는 외곽선으로 두는 알약형 토글 방식을 쓴다.
   - 이유: 선택 상태가 한눈에 구분된다. 어떤 항목에 쓸지는 이 문서에서 정하지 않는다.
5. 홈 '다른 집사들이 만든 간식 세트'와 '베스트 간식 박스'의 카드 위계 (시각 처리만)
   - 기존에 정한 정보만 두고, 이미지를 크게, 글자는 짧고 작게 정리하는 위계로 표현한다.
   - 이유: 정보를 늘리지 않고 이미지로 먼저 끌어서 가볍게 고르는 인상을 만든다.

### 적용하지 않을 부분

- 상단 프로모션 배너 다수, 할인 코드, 기간 한정 문구: '쇼핑몰식 빽빽함' 회피 방향과 충돌한다.
- 하단 FAQ 영역(제안 A): 홈 섹션이 늘어나고 정기배송 관리 기능의 범위도 정해지지 않아 채택하지 않았다.
- 팀(반려견 직원) 소개, 판매처 로고 줄: 3페이지 구성에 없고 핵심 행동과 관련이 없다.
- 박스 종류 4개 중 하나를 고르는 구조: 골라담냥은 맛과 개수를 직접 골라 담는 구성이라 박스 종류 선택은 가져오지 않고, 토글의 표현 방식만 참고한다.
- 후기 영상과 많은 후기, 별도의 베스트셀러 상품 행: 홈 섹션이 늘어나 빽빽해진다.
- 하늘색 계열의 색: 골라담냥의 색 방향(초록 기본, 보라 포인트)과 다르다.

## 전체 정리

### 레퍼런스별 역할

- 오아시스마켓: 초록을 기본으로 삼는 색 방향, 섹션 제목에서 박스 만들기로 이어지는 연결(D)
- Scrumbles: 색 조합 원리(한 계열 + 핵심 버튼만 대비색 + 파스텔 보조), 홈 섹션 배경색 구획(B)
- Bark: P02·P03 오른쪽 영역의 내부 순서와 단일 큰 버튼(C), 여백, 정보 위계, 선택 컨트롤 표현

### 충돌하는 특징과 우선순위 제안

| 항목 | 충돌 내용 | 우선순위 제안과 이유 |
|---|---|---|
| 화면 밀도 | 오아시스 높음, Scrumbles 중간, Bark 낮음 | Bark > Scrumbles > 오아시스. 피할 방향이 쇼핑몰식 빽빽함이고 핵심 행동이 박스 구성이기 때문이다. |
| 배경 처리 | Scrumbles는 색 띠 전환, Bark는 흰 바탕 유지 | 홈은 Scrumbles 방식, P02·P03은 Bark 방식. 홈은 첫인상과 재미가 중요하고, P02·P03은 선택·신청 작업이라 방해 요소를 줄여야 하기 때문이다. |
| 버튼 색 | 오아시스는 초록 계열 일관, Scrumbles는 면 색과 다른 대비색, Bark는 밝은 하늘색 하나 | 가장 중요한 버튼 한 종류는 주변 면과 대비되게 한다. 초록 면 위에서 어떤 색을 쓸지는 결정이 필요하다. |
| 가격·할인 표시 | 오아시스는 강하게 표시, Bark는 가격 단순 표시와 프로모션 다수 | 가격은 박스 만들기의 실시간 표시에서만 강조하고, 나머지에서는 최소화한다. |
| 문구 톤 | 오아시스는 가격·품질 정보 중심, Scrumbles·Bark는 장난스러움 | 발랄하고 유쾌한 인상이 목표라 Scrumbles·Bark 방향으로 하되, 개수·가격·배송 주기는 오아시스처럼 정보를 분명히 한다. |
| 이미지 배경 | Bark는 연한 패널 위에 큰 사진을 일부 튀어나오게, Scrumbles는 파스텔 원형 | 둘 다 쓸 수 있지만 한 화면에서는 하나만 쓴다. |

### 사이트맵·와이어프레임 변경

- 사이트맵(03): 변경 없음.
- 와이어프레임(04): 아래 세 가지를 변경한다.
  - [변경 B] 홈 섹션 사이에 배경색 구획 표시 추가
  - [변경 C] P02의 '내 박스'와 P03의 '구성 확인' 오른쪽 영역에 내부 순서와 버튼 위치를 명시 (구성 → 요약·가격 → 단일 큰 버튼). P02는 B04·B05를 B04 하나로 합침, P03은 B06 위치만 명시
  - [변경 D] 홈 '베스트 간식 박스' 섹션 제목 옆에 '더보기' 링크를 두고 박스 만들기(P02)로 연결
- 채택하지 않은 제안: [제안 A] 홈 하단 FAQ 영역

### 확정하지 않은 것

- 정확한 색상값, 글꼴, 간격, 움직임 수치는 확정하지 않았다. 오아시스와 Bark의 theme-color 메타값은 확인된 값일 뿐 UI 색으로 확정하지 않았다.
- 초록 면 위의 핵심 버튼 색(초록을 유지할지, 보라 계열 같은 대비색을 쓸지)은 결정이 필요하다.
- 확인하지 못한 것: 오아시스의 시각 값(캡처 없음), Scrumbles와 Bark의 첨부 캡처 밖 영역, 모든 사이트의 폰트 이름
