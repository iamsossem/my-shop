## 03. 핵심 가설

**가설 설정 배경 한 줄**

- (초안) 사이트의 핵심 행동이 "박스를 구성하고 정기배송 신청까지 완료하기"이고, 방문자의 첫 번째 필요가 "맛·개수를 내 마음대로 고르기"이기 때문에 이 가설을 세웠습니다.

**IF-THEN**

- (초안) **IF** 간식 카드의 `+`를 누르면 간식 사진이 도시락 칸으로 날아가 채워지는 인터랙션을 넣으면,
- (초안) **THEN** 방문자는 8칸을 끝까지 채워 장바구니에 담고, 정기배송 신청 완료 화면까지 이동한다.

**검증 방향**

- (초안) 핵심 흐름 테스트 케이스 TC-37(PC), TC-38(휴대폰)로 "홈 → 박스 만들기 → 장바구니 → 신청 → 완료"가 끊기지 않는지 확인합니다. 이 케이스는 기능이 동작하는지 보는 것이어서, 방문자가 실제로 끝까지 가는지는 다른 사람이 해 보는 관찰이 필요합니다. 07에서 이어집니다.

### 인터랙션 1. 간식 담기 모션 (P02)

- **무엇을**: 간식 카드의 `+`를 누르면 카드 개수가 1 늘고, 그 간식 사진이 곡선 경로로 날아가 줄어들면서 내 박스의 앞쪽 빈 칸에 들어가 채워집니다. 사진 복사본 6장이 0.04초 간격으로 꼬리처럼 이어지고, 한 장당 1.2초가 걸립니다. 닿은 칸은 0.6초 동안 탄성 있게 튀어 오릅니다. 개수와 합계는 누르는 즉시 바뀝니다. `−`나 채워진 칸을 누르면 그 칸이 비워집니다.
- **왜**: (초안) 03의 IF입니다. 눌렀을 때 내 박스가 채워지는 것이 바로 보이면, 8칸을 채우는 일이 놀이처럼 느껴져 끝까지 담게 된다고 보았습니다. 문서에는 담는 동안 박스와 합계가 계속 보이도록 오른쪽 영역을 화면에 고정했다고 적혀 있습니다.
- **어떻게**: 라이브러리 없이 브라우저 기본 Web Animations API로 구현했습니다(`flyToBox.js`). 곡선은 cubic-bezier(0.45, 0, 0.55, 1)입니다. Codrops "From Product to Cart" 글을 참고했고, 글은 GSAP를 썼지만 이 프로젝트는 쓰지 않았습니다. 터치 기기에서는 사진 1장이 0.6초 만에 날아갑니다. 모션 줄이기 설정이면 날아가지 않고 칸이 바로 채워집니다.

### 인터랙션 2. 8칸 완성과 장바구니 담기 (P02)

- **무엇을**: 마지막 8번째 칸이 차면 도시락이 통통 튀고, 가운데에서 간식 색 반짝이 16개가 터지며, "장바구니 담기" 버튼에 빛이 한 번 지나갑니다. 8칸 전에는 버튼이 투명도 0.4로 비활성입니다. 누르면 도시락 그림 복제본이 상단 "장바구니"로 날아가 작아지고(1초), 배지 숫자가 탄력 있게 튀어 오르며, 박스는 비워지고 화면 아래에 "박스를 장바구니에 담았어요. 다음 박스도 만들어 볼까요?" 알림이 4초간 뜹니다.
- **왜**: (초안) 박스를 완성한 순간을 눈에 띄게 하고, 다음 단계인 장바구니로 시선을 옮기게 하려는 선택입니다. 03의 THEN("장바구니에 담고 신청 화면까지 이동")과 직접 이어집니다.
- **어떻게**: CSS와 Web Animations API입니다. 터치 기기에서는 반짝이를 16개에서 8개로 줄이고, 도시락이나 상단 메뉴가 화면 밖이면 날리지 않고 담은 뒤 배지만 튀어 오르게 합니다. 모션 줄이기 설정에서도 처리했습니다.

### 인터랙션 3. 실시간 합계와 무료배송 진행 바 (P02·P04·P03)

- **무엇을**: 담거나 뺄 때마다 담긴 개수, 상품 합계, 할인, 매달 결제 금액의 숫자가 자리마다 슬롯머신처럼 굴러가며 바뀝니다(0.6초). 30,000원까지 차오르는 무료배송 진행 바가 있고, 다 차면 바에 빛이 흐르고 막 채운 순간 색 조각 14개가 터집니다.
- **왜**: (초안) 문서의 가격 정책이 "담는 즉시 개수와 합계 금액이 바뀐다"입니다. 가격 변화를 바로 보여 주어, 합리적인 정기배송이라는 인상을 전하려는 선택입니다.
- **어떻게**: `RollingText.jsx` 컴포넌트를 P02·P04·P03 요약이 함께 씁니다. 터치 기기에서는 흐르는 빛을 없애고 조각을 14개에서 7개로 줄였습니다.

> (초안) 위 3가지는 문서의 인터랙션 목록에서 신청까지의 흐름과 가장 가까운 것을 골랐습니다. 홈 첫 화면 격자 일그러짐(S01)이나 구성품 위치 표시(S02)를 대신 넣고 싶다면 바꿔도 됩니다.

## 08. 바이브코딩 구현

**협업 방식 한 줄**

- (초안) AI가 7단계(목적 확인 → 페이지 설계 → 디자인 → 에셋 → 인터랙션 → 반응형 → 배포)를 한 단계씩 진행하고, 나는 결과를 보고 "승인 / 수정 요청 / 다시 하기"로 판단했습니다. 문서에 이 진행 규칙이 적혀 있고, 인터랙션은 하나씩 승인받아 적용했다고 되어 있습니다.

**구현 환경**

- React + Vite + JavaScript + 기본 CSS, react-router-dom, React Context(BoxProvider), Web Animations API, React Bits GridDistortion, oxlint, GitHub Actions, GitHub Pages
- AI 툴: Claude, Antigravity

**내가 설계한 것** (문서의 "사용자 답변" 기준)

- 페이지 흐름: 홈 → 박스 만들기 → 장바구니 → 정기배송 신청 → 완료 팝업. 장바구니는 내가 요청해서 추가했고, 상단 메뉴 M04도 "정기배송 신청"에서 "장바구니"로 바꿨습니다.
- 박스 구조: 도시락 1개 = 8칸 = 간식 8팩. 고양이 수 선택은 없애고, 여러 박스가 필요하면 장바구니에 여러 개 담는 방식으로 정했습니다.
- 가격 정책: 간식 6종의 개당 가격 승인, 정기배송 5% 할인, 30,000원 이상 무료배송
- 담기 모션과 슬라이더 같은 인터랙션 방식 승인, 홈 첫 화면 격자 일그러짐 값
- 신청 입력: 로그인 없이 3칸, 빈 칸일 때 안내 문구
- 반응형: 터치 기기 판정을 화면 폭이 아닌 입력 방식으로 정함, 휴대폰 기준 767px
- 모션 줄이기 설정에서 홈 간식 세트 자동 넘김을 멈추도록 한 것

**AI에게 맡긴 것**

- 코드 구현 전반(React 컴포넌트, 스타일, 인터랙션 코드)
- 문서에 "구현 임시값"과 "AI 결정"으로 적힌 값들. 2026-11-17에 내가 정리를 맡겼고, AI가 화면을 확인한 뒤 확정했습니다.
  - 30,000원 미만 배송비 3,000원(신청 1건에 한 번)
  - 홈 베스트 박스와 간식 세트의 예시 구성, 세트 카드 태그
  - 신청 화면 배치와 이미지, 박스가 없을 때 안내, 완료 팝업
  - 인터랙션 수치, 모션 라이브러리를 쓰지 않는 결정, 개수 숫자 튀어 오름을 넣지 않는 결정
  - 3단계 아이콘을 시안의 선 아이콘으로 대체
  - 터치 기기 헤더·배치 값

**내가 직접 판단하고 수정한 것**

- 이미지 배경을 원형 없이 파스텔 단색 판으로 바꿈, 간식 카드 이미지를 카드 가장자리까지 꽉 차게 바꿈 (06 문서: 사용자 수정 반영)
- 홈 베스트 박스 이름 크기를 32/800으로 키움 (사용자 요청)
- 카드 선택 연출을 약하게 조정: 글의 연출(나머지 0.8배·5%·1.6초)은 연달아 담기를 막아서, 나머지 카드 0.96배·40%·약 1초로 줄였습니다.
- 3단계 아이콘 파일(`step-1~3.svg`)이 실제로는 JPEG라서 브라우저에서 열리지 않는 문제가 있었습니다. 파일 이름은 바꾸지 않기로 했고, 화면에는 시안의 선 아이콘이 나옵니다.

**배운 것**

- (초안) 화면을 만든 뒤 PRD를 쓰면서, 와이어프레임의 P04(정기배송 관리)가 실제로는 장바구니(`/cart`)로 바뀐 것을 발견했고, 화면 ID를 지금 만든 사이트 기준으로 다시 맞췄습니다. 문서와 화면이 어긋나기 쉽다는 점을 배웠다고 쓸 수 있습니다.

**처음과 끝을 연결하는 서사**

- (초안) 쇼핑몰처럼 빽빽하고 단계가 많은 구매 과정을 피하려고, 8칸 박스 하나를 채우는 인터랙션으로 맛·개수 선택과 정기배송 신청을 이었습니다.

**검증 근거**

- 테스트 결과가 문서에 없어서 지금은 쓸 수 없습니다.
- 03의 THEN("8칸을 채워 장바구니에 담고, 신청 완료 화면까지 이동한다")이 일어났는지, 통과한 케이스와 테스트한 사람의 실제 반응
- (초안) 예시 문장: "○명이 테스트했고, ○명이 안내 없이 신청 완료 팝업까지 이동했습니다."

**한계 (솔직하게 쓸 것)**

- 사이트는 가상이고 실제 결제·저장이 없어서, 신청 완료는 실제 구매가 아닙니다.
- 테스트 케이스는 기능 동작을 확인하는 것이고, 문서에는 테스트한 사람과 인원이 없습니다. 만든 사람이 직접 한 테스트라면 가설이 검증됐다고 하지 말고 "동작을 확인했다"까지만 쓰세요.

**압축 문장 (2~3문장)**

- (초안) 간식을 8칸 도시락에 담는 인터랙션으로 맛과 개수를 고르는 과정을 신청까지 이었습니다. [테스트한 범위]에서 [확인된 행동]을 확인했습니다. 더 많은 사용자 테스트는 남은 과제입니다.

**마무리 한 문장**

- (초안) 고르는 일이 쉽고 재미있으면, 신청까지의 길이 짧아집니다.
